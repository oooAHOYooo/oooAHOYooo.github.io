Developing these documents through GitHub

  1. Edit the HTML in the repository. Each document is a versioned page instead of a separate Google Doc.
  2. Use a branch for meaningful changes. Name it for the work, such as docs/nonprofit-revision.
  3. Preview locally. Check the page at its real route, including mobile width, before sharing it.
  4. Open a pull request. Use the PR description to explain the change, intended audience, and any facts that still need verification.
  5. Merge the approved version. The public site deploys from the repository; the document history stays attached to the code and commit.
