Documentation / intended behavior

What is the account?

Proposed rule: one AHOY identity follows a person across every surface. Browsing can stay open; personal state should have a clear home.

Identity

One account, one login, one profile. A person should not create separate accounts for Discover, Library, Cards, or Player.

Before login

Anyone can browse Discover, view artists, and understand the system. The account gate appears when someone wants to save, follow, collect, or continue elsewhere.

Library state

Saved music, podcasts, artists, events, and other personal actions belong to the account and are available wherever Library is present.

Ownership state

A save is not ownership. Purchases, card unlocks, and authorized offline copies should each be represented as separate account states.

Cross-surface rule

Discover finds it → Account remembers it → Library organizes it → Cards or commerce may unlock it → Player plays what is authorized.

Failure case

If a person signs in on a new surface, their existing identity and Library should be recognized. If something is unavailable there, explain why instead of silently dropping it.

What is the account?

One identity across Discover, Library, Cards, and Player—or a lighter account only where it earns its keep?

What does ownership mean?

A save, a purchase, a card unlock, and an offline copy should be different states with clear language.

Where do creators enter?

Submission, review, publishing, profile ownership, analytics, and payout are a parallel system that needs its own map.

What is the smallest next step?

Make Discover → Save feel complete before adding more surfaces. The loop should work before the architecture expands.
